# QADAM

**От идеи — к первому шагу.** Платформа, где студенты, разработчики, дизайнеры и фаундеры Казахстана находят единомышленников, публикуют проекты и встречаются на событиях. Публикации бесплатны, без месячных квот, пакетов и оплаты.

## Две версии интерфейса

На экранах до 1023 px исходные мобильные маршруты открывают версию целиком из предоставленного `qadam-main.zip`. 20 файлов экранов, компонентов, данных, Store и стилей в `frontend/src/original-mobile/` сохранены побайтово; контрольные суммы находятся в `archive-manifest.json` и проверяются тестом. По явному выбору владельца сохранены оригинальные локальный демо-вход, данные, чаты и localStorage. Они отделены от серверных аккаунтов и публикаций.

Мобильные `/`, `/welcome`, `/signin`, `/places`, `/feed`, `/messages`, `/messages/:id`, `/profile`, `/add` принадлежат архивной версии. Её нижняя навигация сохраняет четыре исходных пункта. Дополнительной панели над экраном нет. В `frontend/src/original-mobile-extras/integration.css` находятся согласованные визуальные изменения категорий: отступ под переключателем 36 px, плавный подъём на 4 px без смены порядка наложения и растяжение четвёртой карточки Events до низа экрана. Нижняя навигация находится поверх карточки; на коротком экране остаётся прокрутка. При ширине 520–1023 px сохраняется рамка шириной 400 px.

Десктоп и канонические серверные страницы используют действующий API и серверную сессию. Серверный вход на телефоне — `/account/signin`, профиль — `/account/profile`; на десктопе основные адреса — `/signin` и `/profile`. Серверные `/map`, `/create`, `/chats`, `/projects`, `/p/:id`, `/u/:id` доступны на любой ширине. Локальный мобильный вход не авторизует серверный аккаунт.

Стили архива изолированы в отдельном CSS без правки исходного `styles.css`: `node frontend/scripts/scope-original-mobile.mjs`. Переводы и переключение темы действуют в серверных разделах и на десктопе; исходные мобильные тексты и палитра сохраняются.

| Часть | Стек | Папка |
|---|---|---|
| Фронтенд | Vite + React 18 + TypeScript, Leaflet | [frontend/](./frontend) |
| Бэкенд | Node.js + Express 5 + TypeScript, SQLite (`node:sqlite`) | [backend/](./backend) |

SQLite хранится в `backend/data/qadam.db`; отдельный сервер базы для локального запуска не нужен. API описан в [backend/README.md](./backend/README.md), устройство интерфейса — в [frontend/README.md](./frontend/README.md).

## Быстрый старт

Нужны **Node.js 22.13+** и **npm**. Рекомендуемая основная версия Node указана в `.nvmrc`. Команды выполняются из корня проекта:

```bash
npm ci
npm run dev
```

Открой **http://localhost:5173/**. API работает на **http://localhost:3001**; Vite проксирует `/api` на него. После намеренного изменения зависимостей используй `npm install`, чтобы обновить lockfile. Остановить оба процесса можно одним `Ctrl+C`.

В dev пустая база по умолчанию заполняется демо-данными. В серверной форме входа можно зарегистрироваться, войти по email и паролю или воспользоваться разрешённым сервером демо-входом. Его доступность сообщает `GET /api/auth/options`; обычный демо-аккаунт использует контент из [backend/src/seed-data.ts](./backend/src/seed-data.ts). В production демо-вход и автозаполнение пустой БД выключены по умолчанию и управляются отдельными настройками. Подробности — в документации бэкенда.

## Команды и проверки

| Команда | Что делает |
|---|---|
| `npm run dev` | API и фронтенд с перезапуском при изменениях |
| `npm test` | Интеграционные проверки API и тесты логики фронтенда |
| `npm run typecheck` | Проверка типов обеих частей |
| `npm run build` | Проверка типов и сборка в `frontend/dist` и `backend/dist` |
| `npm start` | Собранный API и фронтенд на одном сервере, по умолчанию порт 3001 |
| `npm run seed` | Удаляет текущие данные базы и создаёт демо-данные заново |

Части можно запускать отдельно: `npm run dev -w backend` и `npm run dev -w frontend`. CI в [.github/workflows/ci.yml](./.github/workflows/ci.yml) выполняет `npm ci`, `npm test` и `npm run build`. Проверки логики и сборки дополняются проверкой интерфейса в браузере.

## Серверные маршруты и навигация

На телефоне архивные адреса из раздела выше сохраняют исходное поведение. Таблица описывает серверные страницы:

| Адрес | Страница |
|---|---|
| `/` | Главная на десктопе: поиск, категории, свежие публикации выбранного города, карта, FAQ |
| `/map` | Возможности рядом: фильтры, список или карта |
| `/p/:id` | Событие, идея, вакансия или встреча |
| `/signin` | Вход и регистрация на десктопе |
| `/account/signin` | Серверный вход и регистрация на телефоне |
| `/create` 🔒 | Создание публикации, предпросмотр и черновик |
| `/chats`, `/chats/:id` 🔒 | Список диалогов и выбранная переписка |
| `/profile` 🔒 | Свой серверный профиль на десктопе |
| `/account/profile` 🔒 | Свой серверный профиль на телефоне |
| `/u/:id` | Публичный профиль пользователя |
| `/projects` 🔒 | Свои проекты и проекты, в которых пользователь участвует |

🔒 — требуется серверный вход. После входа восстанавливается внутренний адрес вместе с query и hash. При ошибке проверки сессии доступна повторная попытка; сетевой сбой сам по себе не считается выходом.

У серверных страниц на узком экране есть своя нижняя навигация. `/chats` показывает список, `/chats/:id` — переписку с кнопкой «Все чаты»; на широком экране они расположены рядом. Это отдельные страницы от демонстрационных `/messages` архивной версии.

На десктопе старые адреса перенаправляются с сохранением query, hash и идентификатора диалога:

| Старый адрес | Новый адрес |
|---|---|
| `/welcome` | `/` |
| `/places` | `/map` |
| `/feed` | `/map?view=list`, если режим не задан явно |
| `/add` | `/create` |
| `/messages` | `/chats` |
| `/messages/:id` | `/chats/:id` |

Старый `category=meetups/jobs/ideas/events` преобразуется в `kind=meetup/job/idea/event`. Например, `/feed?category=events#results` на десктопе открывает `/map?kind=event&view=list#results`.

## Карта, публикации и черновики

Карты используют **Leaflet и тайлы OpenStreetMap**; API-ключ не нужен. Фильтры серверной карты хранятся в URL: `q`, `kind`, `city`, `online=1`, `view=map/list`. Ссылка `/map?focus=:id` выбирает город и точку публикации независимо от ранее выбранного города. Смена города или фильтра снимает выделение. Back/Forward и обновление страницы восстанавливают параметры. Карта учитывает изменение размеров контейнера и не перемещает вид при нулевом размере скрытого блока.

Для события серверная форма требует дату, начало и окончание, место и точку на карте. В API передаются `date` в формате `YYYY-MM-DD`, `time` как диапазон местного времени `HH:MM–HH:MM`, `place` и `coords: [широта, долгота]`. Окончание должно быть позже начала. Точку можно выбрать на карте или указать координатами.

Черновик сохраняется вручную кнопкой «Черновик» / «Сохранить черновик», отдельно для каждого пользователя: `qadam.site.draft.<userId>`. Перед отправкой форма дополнительно сохраняет снимок и ключ попытки `qadam.site.publication-attempt.<userId>`. Независимая логика в `frontend/src/site/publication-attempt.ts` повторно использует прежний `Idempotency-Key` для того же запроса: потерянный успешный ответ не создаёт вторую публикацию. Изменение содержимого начинает новую операцию. При 409/410 форма предлагает проверить «Мои проекты» и явно начать новую отправку. Старые несовместимые попытки также требуют такого подтверждения.

Локальные записи удаляются после подтверждённого успеха. При недоступном хранилище защита повторов остаётся в памяти страницы, но восстановление после перезагрузки не гарантируется. Выбранный город хранится локально; серверные аккаунт, публикации, заявки и сообщения загружаются из API. Локальные данные архивной мобильной версии хранятся отдельно.

Серверный чат отправляет текстовые сообщения. Загрузка и скачивание вложений не реализованы; демо-история может содержать подпись файла. Принятие и отклонение заявок с управлением составом команды также не реализованы.

## Языки и оформление

В серверном интерфейсе доступны **RU / ҚАЗ / EN** и светлая/тёмная темы. Выбор хранится в `qadam.site.language` и `qadam.site.theme`, применяется до запуска React и синхронизируется между вкладками. При недоступном хранилище переключение работает до перезагрузки. Пользовательские публикации, имена и сообщения автоматически не переводятся.

Тёмный баннер главной — `frontend/public/img/hero-qadam-green.png`, светлый — отдельный `hero-qadam-light.png`. Их выбор следует теме; исходный тёмный файл не заменяется. Тексты поверх баннера переводятся и используют цвет выбранной темы. Архивная мобильная версия сохраняет собственное оформление.

## Структура

```text
.
├── package.json                       # workspaces и общие команды
├── .github/workflows/ci.yml            # тесты и сборка
├── backend/                           # API, SQLite и сессии
└── frontend/
    ├── public/img/                    # изображения и варианты героя
    ├── tests/                         # логика и контроль оригинальных файлов
    └── src/
        ├── main.tsx, App.tsx          # BrowserRouter, SiteProvider, выбор версии
        ├── original-mobile/           # 20 неизменных файлов из ZIP
        ├── original-mobile-extras/    # оболочка и изолированные стили
        ├── useIsDesktop.ts            # граница 1024 px
        ├── site.css, responsive.css   # серверный интерфейс
        ├── theme.css                  # светлая и тёмная темы
        └── site/
            ├── SiteApp.tsx            # серверные маршруты и навигация
            ├── api.ts, state.tsx      # API, серверная сессия и данные
            ├── publication-attempt.ts # независимая защита повторной публикации
            ├── i18n.ts, locales/      # RU / ҚАЗ / EN
            ├── routes.ts             # совместимость адресов на десктопе
            ├── components/
            └── screens/
```

Корневые `frontend/src/screens/`, `components/`, `data/`, `store.tsx`, `styles.css` остаются справочной копией. Активный оригинал — `src/original-mobile/`; серверный интерфейс — `src/site/`. Интеграционные изменения мобильной версии вноси в `src/original-mobile-extras/`, сохраняя исходные 20 файлов.

## Настройки и частые проблемы

Настройки API находятся в [backend/.env.example](./backend/.env.example): порт, путь к базе, демо-режим и cookie. Для dev значения по умолчанию позволяют запустить проект без `.env`. Для размещения используй `NODE_ENV=production`, постоянное хранилище базы и HTTPS; детали — в документации бэкенда.

| Симптом | Что проверить |
|---|---|
| `No such built-in module: node:sqlite` | `node -v`: нужна версия 22.13 или новее |
| Плашка ошибки подключения | Убедись, что API работает; после восстановления нажми «Повторить» |
| `EADDRINUSE :3001` | Освободи порт или измени `PORT` в `backend/.env` и `API_URL` для Vite |
| Порт 5173 занят | Vite выберет другой; используй адрес из его вывода |
| Карта без тайлов | Проверь доступ к `tile.openstreetmap.org` |
| Открыть с телефона в той же Wi-Fi сети | Запусти API и `npm run dev -w frontend -- --host`, открой сетевой адрес Vite |
| Пересоздать локальные демо-данные | `npm run seed`; команда удаляет существующие данные |

## Для ИИ-ассистента и контрибьютора

1. Проверь `node -v`, установи зависимости командой `npm ci`, запускай проект из корня.
2. Готовность API проверь запросом `http://localhost:5173/api/health`: ожидается `{"ok":true}`.
3. Сохраняй разделение архивного локального Store и серверного SiteProvider; не меняй файлы архива без прямого запроса.
4. Для API используй `backend/src/routes/` и Zod; обновляй типы и вызовы в `frontend/src/site/api.ts`.
5. Перед передачей изменений выполни `npm test` и `npm run build`. Проверь широкое/узкое окно, переход между версиями, карту, публикацию/чат и восстановление подключения.
6. Не добавляй в репозиторий базу `backend/data/`, `.env`, зависимости и `dist/`.

Краткие инструкции для агентов — в [AGENTS.md](./AGENTS.md).
