# QADAM — фронтенд

Приложение на Vite, React 18 и TypeScript. `src/App.tsx` сохраняет один серверный SiteProvider выше переключения представлений по ширине и адресу. Десктоп и серверные разделы открывают `src/site/SiteApp.tsx`. На телефонах исходные мобильные маршруты используют точную копию из предоставленного ZIP в `src/original-mobile/`: 20 исходных файлов не изменяются, их SHA-256 проверяется тестом.

Публикации бесплатны, без месячных квот, пакетов, расчёта цены и оплаты.

## Оригинальная мобильная версия

По явному выбору владельца мобильная копия сохраняет оригинальное демо-поведение: локальные вход, публикации, сохранённое и тестовые чаты отделены от серверной базы. В `src/original-mobile-extras/` находятся оболочка маршрутов, изоляция CSS и согласованные визуальные изменения. Дополнительной панели над `.screen` нет. Четыре исходных пункта нижней навигации и оригинальные файлы экранов сохранены.

Генерация изолированного CSS из корня проекта:

```bash
node frontend/scripts/scope-original-mobile.mjs
```

Не редактируй `src/original-mobile/styles.css` или сгенерированный `archive-scoped.css` вручную для интеграционных изменений. Вноси такие изменения в `original-mobile-extras/integration.css`. Там реализованы отступ 36 px после Categories/Map, плавный подъём категории на 4 px, поддержка удержания/фокуса и reduced motion. Порядок карточек при наложении сохраняется: следующая перекрывает низ предыдущей. Events растягивается до нижней границы экрана; nav накладывается поверх, текст остаётся выше неё. При недостаточной высоте экран прокручивается. На ширине 520–1023 px сохраняется рамка 400 px, ограниченная доступной высотой.

Архив использует отдельные ключи localStorage, включая `qadam.authed`, `qadam.created`, `qadam.createdMine`, `qadam.saved`, `qadam.joined`, `qadam.messagesSent`. Они не подтверждают серверную авторизацию и не импортируются в API. Переводы и темы действуют в серверных разделах; исходные мобильные тексты и палитра остаются как в архиве.

## Запуск и проверки

Запускай из **корня** репозитория, чтобы одновременно поднять API:

```bash
npm ci
npm run dev
```

Нужен Node 22.13+. Фронтенд: http://localhost:5173, API: http://localhost:3001. Только фронтенд: `npm run dev -w frontend`; при этом API запускается отдельно. Vite проксирует `/api` на `API_URL`, по умолчанию — `http://localhost:3001`.

Из корня доступны `npm test`, `npm run typecheck`, `npm run build`. Только тесты фронтенда: `npm test -w frontend`. Они используют `node:test` и `tsx` и проверяют маршруты, безопасный возврат после входа, API-клиент, фильтры/геометрию карты, повтор публикации, синхронизацию чатов, переводы и неизменность архива. CI выполняет тесты workspaces и сборку. Адаптивность, клавиатуру и сценарии пользователя дополнительно проверяй в браузере.

## Маршруты и авторизация

На телефонах до 1023 px `/`, `/welcome`, `/signin`, `/places`, `/feed`, `/messages`, `/messages/:id`, `/profile`, `/add` открывают архивную версию. Остальные серверные адреса ниже работают на любой ширине. Основные серверные вход/профиль на телефоне вынесены в `/account/signin` и `/account/profile`, чтобы не менять архивные страницы.

| Серверный маршрут | Назначение |
|---|---|
| `/` | Главная на десктопе: поиск, категории, публикации города, карта, FAQ |
| `/map` | Фильтры, список и карта возможностей |
| `/p/:id` | Публикация и действия «Сохранить», «Я пойду» или отклик автору |
| `/signin` | Вход по email/паролю, регистрация и разрешённый демо-вход на десктопе |
| `/account/signin` | Серверная форма входа на телефоне |
| `/create` | Создание публикации и черновик; нужен вход |
| `/chats`, `/chats/:id` | Список диалогов и переписка; нужен вход |
| `/profile` | Серверный профиль на десктопе; нужен вход |
| `/account/profile` | Серверный профиль на телефоне; нужен вход |
| `/u/:id` | Публичный профиль пользователя |
| `/projects` | Свои проекты и участие в других; нужен вход |

Закрытые страницы сохраняют `pathname + search + hash` и возвращают пользователя на внутренний адрес после входа. Внешние return URL и возврат на саму страницу входа отклоняются. Пока сессия не проверена, закрытая страница ожидает результат. При сетевой ошибке доступна повторная проверка; пользователь не считается вышедшим. Выход очищает состояние после успешного ответа API.

Демо-кнопка показывается по `GET /api/auth/options`; ошибка загрузки условий не должна разрешать демо. Обычный серверный демо-вход сохраняет безопасный адрес возврата и не заменяет локальный вход архивной версии. В production серверный демо-вход выключен по умолчанию, но может быть явно разрешён настройкой сервера. Само скрытие кнопки не заменяет серверную проверку.

Совместимость старых адресов **на десктопе** реализована в `src/site/routes.ts`:

| Старый маршрут | Перенаправление |
|---|---|
| `/welcome` | `/` |
| `/places` | `/map` |
| `/feed` | `/map`, режим `list`, если `view` не задан |
| `/add` | `/create` |
| `/messages` | `/chats` |
| `/messages/:id` | `/chats/:id` |

Query, hash и id сохраняются; `category=meetups/jobs/ideas/events` преобразуется в `kind=meetup/job/idea/event`. Например, `/messages/c_123?from=profile#last` на десктопе открывает `/chats/c_123?from=profile#last`. На телефоне этот адрес остаётся архивным чатом.

## Языки, темы и навигация серверной версии

Справа сверху есть выбор языка **RU / ҚАЗ / EN**. Он переводит интерфейс главной, поиска/карты, публикаций, форм входа/создания/профиля, проектов и чатов. Выбор `ru` / `kk` / `en` сохраняется в `localStorage` (`qadam.site.language`), применяется в `index.html` до запуска React и синхронизируется между вкладками. Без доступа к хранилищу язык работает до перезагрузки. `<html lang>` и формат дат/чисел следуют выбору. Переключение не меняет API-значения городов/категорий, черновики, ключи повтора или аккаунт.

Общая логика — `src/site/i18n.ts`, чистые функции — `i18n-core.ts`, каталоги казахского и английского — `locales/`. Русские строки служат исходными ключами; параметры сообщений именованные (`{count}`, `{city}`), их набор проверяется тестами. Пользовательские имена, публикации, сообщения и тексты внутри загруженных изображений не переводятся автоматически. Если сервер вернёт новую неизвестную ошибку, показывается её исходный текст.

В верхней панели серверного интерфейса доступна кнопка солнца/луны. По умолчанию используется исходная тёмная тема. Выбор сохраняется в `localStorage` (`qadam.site.theme`), применяется до запуска React и синхронизируется между вкладками. Если хранилище недоступно, переключатель работает до перезагрузки. Карты используют ту же тему; смена оформления сохраняет сессию, маршрут, фильтры и заполненные формы.

Баннер главной следует теме: `public/img/hero-qadam-green.png` — исходный тёмный вариант, `public/img/hero-qadam-light.png` — отдельная светлая иллюстрация. Смена изображения сохраняет размеры баннера, текст поверх него получает контрастный цвет. Изображения и адаптивный crop не заменяют тексты и оформление архивной мобильной версии.

У серверных страниц на узком экране есть собственная нижняя навигация с доступом к карте, проектам, созданию, чатам и `/account/profile`. Гостю закрытые разделы предлагают войти через `/account/signin` с сохранением назначения. Её DOM и данные отделены от четырёх пунктов архивной навигации.

## Серверные чаты

На узком экране `/chats` показывает список, а `/chats/:id` — выбранную переписку с кнопкой «Все чаты». На широком экране список и переписка стоят рядом. Изменение размера окна не создаёт отдельную сессию.

Есть поиск диалогов, фильтр непрочитанных, текстовая отправка и повтор после ошибки. Новые сообщения приходят последовательным опросом API без перекрывающихся запросов; скрытая вкладка не опрашивается. Чтение отмечается до последнего реально загруженного сообщения только при видимом низе переписки. При просмотре истории новые сообщения не прокручивают её принудительно к концу; кнопка «Новые сообщения» позволяет перейти вниз.

Вложения пока нельзя загрузить или скачать. Демо-история может отображать название и размер файла без скачивания. Принятие и отклонение заявок, меняющее состав команды, не реализовано. Архивные `/messages` сохраняют демонстрационное поведение ZIP.

## Карта и фильтры

Карты используют Leaflet с тайлами OpenStreetMap. Ключ не нужен. Серверный `SiteMap` обновляет размеры при изменении контейнера; маршрут и сессия при этом не меняются. Скрытый контейнер нулевого размера не должен запускать перемещение карты с некорректными координатами.

| Параметр `/map` | Значение |
|---|---|
| `q` | Поисковый запрос |
| `kind` | `meetup`, `job`, `idea` или `event` |
| `city` | Выбранный город |
| `online=1` | Только публикации с онлайн-участием |
| `view` | `map` или `list`; по умолчанию карта |
| `focus` | ID публикации для выбора города, центра и карточки |
| `filters=1` | Открытая панель фильтров |

Некорректный `kind` удаляется. `focus` выбирает город публикации независимо от сохранённого города; несовместимые фильтры снимаются. Новая смена города, категории, онлайн-фильтра или поиска сбрасывает `focus`. Back/Forward и обновление страницы восстанавливают параметры из URL. Поиск и категории серверной главной передают город; «Возможности рядом» использует реальные публикации этого города.

## Публикации и локальные данные

Форма `/create` отправляет публикацию через API и открывает её страницу после успеха. Дополнительного запроса условий перед отправкой нет. Для события требуются дата, начало и окончание, адрес/название места и точка на карте. `date` передаётся как `YYYY-MM-DD`, `time` — `HH:MM–HH:MM` по местному времени события, `place` — строка, `coords` — `[широта, долгота]`. Окончание должно быть позже начала. `LocationPicker` позволяет выбрать точку на карте или вручную указать координаты.

Кнопки «Черновик» и «Сохранить черновик» записывают форму в `localStorage` под ключом `qadam.site.draft.<userId>`. Черновик принадлежит конкретному пользователю в текущем браузере; после успешной публикации он удаляется. Сохранение ручное; дополнительно снимок формы сохраняется перед отправкой для восстановления неопределённого результата. Синхронизации между устройствами нет. Город хранится в `qadam.site.city`. Авторизация, профиль, публикации, заявки, сохранённое и сообщения загружаются с сервера; session cookie не читается кодом приложения.

Независимые helpers в `src/site/publication-attempt.ts` сохраняют незавершённую попытку в `qadam.site.publication-attempt.<userId>` и передают её ключ через `Idempotency-Key`. Повтор того же запроса использует прежний ключ: потерянный успешный ответ не должен создавать вторую публикацию. Изменение содержимого начинает новую операцию. После подтверждённого успеха запись попытки удаляется. Без доступа к `localStorage` защита остаётся для повторов в памяти текущей страницы, но не гарантируется после её перезагрузки.

При 409/410 отправка прежней попытки блокируется. Пользователь сначала проверяет «Мои проекты», затем явно выбирает «Начать новую отправку». Старые несовместимые снимки также не преобразуются автоматически в новую публикацию; личные поля черновика сохраняются. Контракт повторов и серверные правила — в [backend/README.md](../backend/README.md).

## Где менять код

- `src/main.tsx`, `src/App.tsx` — BrowserRouter, единый SiteProvider и переключение версии.
- `src/site/app-surface.ts`, `src/useIsDesktop.ts` — выбор серверных/архивных адресов и граница 1024 px.
- `src/original-mobile/` — 20 неизменных файлов из ZIP; `archive-manifest.json` — контрольные суммы.
- `src/original-mobile-extras/OriginalMobileApp.tsx`, `integration.css`, `archive-scoped.css` — интеграция и scoped оформление архива.
- `src/site/SiteApp.tsx` — серверные маршруты, закрытые страницы, уведомления о подключении и навигация.
- `src/site/api.ts` — API-клиент, типы, отмена запросов, таймауты и обработка завершившейся сессии.
- `src/site/publication-attempt.ts` — независимая защита повторной публикации.
- `src/site/state.tsx` — текущий пользователь, публикации, сохранённое, участие и заявки.
- `src/site/data.ts`, `src/site/i18n.ts`, `src/site/locales/` — типы/справочники, форматирование и переводы.
- `src/site/components/` — Header, MobileNav, SiteMap, LocationPicker и общий UI.
- `src/site/screens/` — страницы; `screens/chatSync.ts` — синхронизация переписки.
- `src/base.css`, `src/site.css`, `src/responsive.css`, `src/theme.css` — серверные стили и темы.
- `src/mobile-original.css`, `src/mobile-forms.css`, `src/mobile-community.css` — адаптация серверных страниц на телефоне.
- `public/img/` — изображения; `tests/` — тесты логики и неизменности архива.

Корневые `src/screens/`, `src/components/`, `src/data/`, `src/store.tsx`, `src/styles.css` остаются справочной копией. Серверные изменения вноси в `src/site/`, интеграцию архива — в `src/original-mobile-extras/`. Исходные 20 файлов архива оставляй неизменными.
