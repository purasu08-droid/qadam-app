# Проверка цен и бесплатного пилота

Проверять на отдельной временной базе. Настоящих платежей и активации продвижения в этой версии нет. Подтверждения студентов и кредиты для тестов выдаёт доверенная серверная fixture/CLI либо назначенный администратор своего Campus через защищённый API кабинета. Самостоятельной выдачи прав студентом нет. Границы ролей и tenant-проверки — в [campus-qa.md](./campus-qa.md).

Браузерные сценарии тарифов относятся к desktop web. В мобильной версии из исходного архива разделов тарифов и Campus нет; API и сохранённые права от ширины экрана не зависят. `npm run seed` отказывает при защищённой истории публикаций/биллинга/Campus; для проверки выбирать отдельный `DB_PATH`, рабочую БД не сбрасывать.

## Основные сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| `preview`, новый пользователь: создать первую и вторую публикации | Обе создаются бесплатно. `usedPublications` становится 2, `freeRemaining` — 0. Первая и вторая фактически имеют основание `pilot`; после первой будущая цена дополнительной публикации — 500 ₸ или 250 ₸ для подтверждённого студента |
| `enforced`, новый пользователь: первая публикация, затем вторая без Campus | Первая проходит по `monthly_free`; вторая получает `402 PAYMENT_REQUIRED`. Не создаются ни вторая публикация, ни дополнительная запись использования; списаний нет |
| Подтверждённый студент с уже использованной месячной квотой | Серверная цена дополнительной публикации — 250 ₸; для `promotion3` — 250 ₸, для `promotion7` — 500 ₸. Изменение email или поля профиля не выдаёт подтверждение |
| Просроченное или ещё не вступившее в силу подтверждение студента | Обычная цена — 500 / 500 / 1 000 ₸. Проверять точное мгновение начала и истечения подтверждения, не только календарный день |
| `enforced`, доступен кредит Campus на публикацию, месячная квота ещё цела | Первая публикация использует `monthly_free`, остаток Campus не меняется. Следующая использует один кредит Campus, фактическая цена студенту 0 |
| `preview`, доступен Campus, месячная квота уже использована | Публикация проходит с `source='pilot'`, `amountDue=0`, `expectedSource='campus'`; кредит Campus не расходуется |
| Campus истёк, ещё не действует, исчерпан или выдан только на другую услугу | Он не покрывает дополнительную публикацию. Для `enforced` она заблокирована с 402; в пилоте остаётся бесплатной |
| Повторять GET `/billing/quote` и `/billing/me`, открывать `/pricing` | Не создаются публикации, записи использования, платежи или активации; остатки Campus не уменьшаются |
| Невалидная форма или ошибка в транзакции создания | Не расходуются ни месячная квота, ни Campus; не остаётся частично созданного проекта/публикации |
| Удалить успешную публикацию и создать следующую в том же месяце | Удаление не возвращает бесплатный слот и не восстанавливает израсходованный Campus. История использования сохраняется |
| Запустить приложение повторно на существующей базе | Старые публикации с автором учитываются в своём исходном месяце как `legacy`, без вымышленных платежей; повторный старт не удваивает учёт |
| Две формы/вкладки создают первые публикации одновременно в `enforced` | Квоту нельзя использовать дважды: одна публикация получает бесплатный слот; вторая требует Campus или получает 402. Финальная проверка атомарна, старый quote не даёт отдельного права |

## Повтор создания после неопределённого ответа

`POST /api/opportunities` принимает необязательный `Idempotency-Key`: 1–128 печатных ASCII-символов без пробелов. Проверить:

| Сценарий | Ожидаемый результат |
|---|---|
| Сервер создал публикацию, но клиент потерял ответ; повторить тем же пользователем, ключом и телом | `201` с тем же ID; одна публикация, один проект, одна запись usage и не более одного расхода Campus |
| После первого успеха квота/последний Campus закончились; повторить прежний ключ | Возвращается прежний результат до нового тарифного gate; повтор не получает 402 как новая операция |
| Тот же ключ, другое валидированное тело | `409 IDEMPOTENCY_CONFLICT`, без дополнительной публикации или расхода |
| Тот же ключ использует другой пользователь | Независимая операция другого аккаунта; первый результат не раскрывается |
| Успешный результат удалён, затем повторён прежний ключ | `410 IDEMPOTENCY_GONE`; публикация не воссоздаётся, квота не возвращается |
| Первый запрос не прошёл валидацию или получил 402 | Ключ не занят: после исправления данных/выдачи покрытия запрос с ним может пройти |
| Разный порядок полей JSON при том же валидированном содержимом | Тот же результат, а не конфликт из-за порядка полей |

### Совместимость выпусков

- Сохранить успешный ключ из нейтральной `publication_requests`, восстановить API тарифов и повторить: возвращается исходный ID до нового gate, даже если сейчас нет квоты. Новых публикаций, использования и расхода Campus нет.
- Проверить прежний ключ из `billing_publication_requests`: действует та же гарантия; старая строка не меняется, новая нейтральная строка для повтора не создаётся.
- Для одного пользователя/ключа подготовить обе записи с одинаковым результатом и совместимым телом: один replay. Разные ID или несовместимое тело хотя бы одной записи дают 409 без создания и расхода.
- Личная публикация выпуска без тарифов с проигнорированным `campusId` остаётся личной при повторе: не требуется новое членство, вуз не привязывается, кредит не расходуется.
- У новых записей `hash_version='v2'`: добавление Campus к личной форме, смена Campus A на B и удаление Campus из первоначального тела под прежним ключом дают 409. Совместимый hash без Campus разрешён только историческим строкам `neutral`.
- При старте сохранившиеся личные публикации и удалённые результаты нейтрального ledger учитываются по одному разу как `legacy` в исходном календарном месяце; цена 0, Campus не расходуется. Повторный старт не удваивает учёт и не меняет контент. Бесплатный пилот остаётся без лимита.

На фронтенде потеря ответа и последующая перезагрузка не должны превращать сохранённую попытку `qadam.site.publication-attempt.<userId>` в новое создание. Восстановить исходные данные и повторить с прежним ключом; даже если обновлённый quote уже блокирует новую публикацию, должен быть доступен запрос результата прежней операции. Изменённая форма получает новый ключ и проходит обычную тарифную проверку. Успех очищает попытку; недоступный `localStorage` ограничивает восстановление текущей страницей. Старые клиенты без заголовка остаются совместимы, но отдельные повторные запросы могут создать дубли.

При `409 IDEMPOTENCY_CONFLICT` или `410 IDEMPOTENCY_GONE` прежняя попытка должна быть заблокирована. Интерфейс предлагает сначала проверить «Мои проекты», затем явно выбрать «Начать новую отправку». Проверить, что это действие сбрасывает прежний ключ, запрашивает новые условия и не создаёт публикацию само. Следующая отправка получает новый ключ и проходит обычную проверку квоты/Campus. Повтор старого ключа не должен запускаться бесконечно или неявно заменяться новым.

## Граница месяца

Период вычисляет сервер в `Asia/Almaty`. Проверить два соседних мгновения:

- `2026-10-31T18:59:59.999Z` → `period: '2026-10'`.
- `2026-10-31T19:00:00.000Z` → `period: '2026-11'`, новая месячная квота.

Дополнительно проверить декабрь → январь и февраль високосного года. Изменение часового пояса браузера не должно менять результат. Quote, полученный до границы, не фиксирует условия: решает время финальной серверной транзакции.

## Продвижение и права

1. Владелец получает расчёт `/billing/quote?service=promotion3&opportunityId=<своя публикация>`; для 7 дней — `promotion7`. Месячная бесплатная публикация не делает продвижение бесплатным.
2. Без `opportunityId` — `400 OPPORTUNITY_REQUIRED`, чужая публикация — `403 NOT_OWNER`, отсутствующая — `404 OPPORTUNITY_NOT_FOUND`. Без сессии — 401.
3. Даже при цене 0 из-за Campus поле `promotionActivationAvailable` остаётся `false`. После просмотра расчёта выдача, порядок публикаций и остаток кредитов не меняются.
4. Подмена клиентом `studentVerified`, цены, `source`, периода или Campus не меняет решение сервера. Самостоятельное подтверждение и поддельные реквизиты оплаты не поддерживаются.

## Локальная выдача прав

Команды из `backend/README.md` проверять на временной БД с зарегистрированным пользователем:

- `billing:student`: допустимы только `admin`/`university`; необязательный срок должен быть будущей ISO-датой с зоной; повтор обновляет статус. Несуществующий email, неподдерживаемый source и прошедший срок отклоняются.
- `billing:student --revoke`: статус исчезает; сочетание с полями выдачи отклоняется. Тариф в следующем quote становится обычным; отзывание статуса само по себе не имитирует платёж.
- `billing:grant`: целая квота 1–100 000, конкретная услуга, существующий email, вуз и будущий срок обязательны. Начало до окончания; даты с offset нормализуются в UTC. Неправильные аргументы не создают частичный кредит.
- Эти команды доступны только доверенной стороне с локальным доступом к серверу/БД. У обычного пользователя нет HTTP-метода самоподтверждения или выдачи Campus; изменение профиля прав не даёт.

## Проверка интерфейса

- `/pricing` показывает тарифы из API, а в пилоте явно сообщает, что все публикации бесплатны, оплаты и списаний нет. Кабинет Campus описан как работающая функция, а активация продвижения и платёжный портал не выдаются за готовые.
- `/create` различает будущую цену и фактические 0 ₸ в пилоте. Для `monthly_free` и Campus не показывает повторную оплату.
- При 402 или потере связи форма не показывает успех и не удаляет черновик; доступны повторный расчёт/сохранение черновика. После получения нового quote кнопка соответствует текущим условиям.
- При успешном, но уже устаревшем quote с `canPublish=false` доступно «Обновить расчёт»: после начала нового месяца либо выдачи Campus администратором пользователь может получить новые условия без перезагрузки страницы. Сам пересчёт не создаёт публикацию и не расходует кредит; при ошибке запроса не возникает ложного разрешения на новое размещение.
- Смена аккаунта не переносит чужой студенческий статус, Campus, месячный счётчик или результат quote. Повторная проверка после истечения кредита/подтверждения использует новые данные сервера.
- При сужении экрана мобильная версия из архива не получает разделы тарифов/Campus. Выбор сравнительной колонки студенческих цен в desktop web не меняет фактическую верификацию пользователя.
- У разовых услуг нет текста об автоматическом продлении, регулярных списаниях или готовом платёжном checkout. Цена Campus остаётся неопределённой.

До включения настоящих платежей отдельно потребуется проверка подтверждения платёжного провайдера и связь платёжной операции с идемпотентным созданием. Поддержка `Idempotency-Key` уже защищает создание публикации, но не является платёжной системой и не подтверждает получение денег.
