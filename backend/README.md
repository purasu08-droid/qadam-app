# QADAM — бэкенд

REST API для сайта: Node.js + TypeScript + Express 5, база SQLite через встроенный модуль `node:sqlite`
(нужен **Node 22.13+**, нативных зависимостей и отдельного сервера БД нет).

Обычно запускается из корня репозитория вместе с фронтендом: `npm run dev` (см. корневой README).
Отдельно — из этой папки:

```bash
npm run dev        # http://localhost:3001, перезапуск при изменениях (tsx watch)
npm run seed       # пересоздать базу с демо-данными
npm run build      # tsc → dist/
npm start          # node dist/index.js (+ раздаёт ../frontend/dist, если он собран)
npm run typecheck
npm test           # интеграционные тесты API с отдельной временной SQLite, без сетевого сервера
```

## Настройки

Скопируй `.env.example` в `.env` (необязательно — у всех значений есть дефолты).

| Переменная | По умолчанию | Что это |
|---|---|---|
| `PORT` | `3001` | Порт API |
| `DB_PATH` | `./data/qadam.db` | Файл SQLite (относительно `backend/`). Создаётся сам и заполняется демо-данными, если пустой |
| `NODE_ENV` | — | При `production` демо-вход и автоматический сид отключены по умолчанию |
| `ALLOW_DEMO_LOGIN` | `true` в dev, `false` в production | Включить/выключить вход в общий демо-аккаунт |
| `SEED_DEMO_DATA` | `true` в dev, `false` в production | Автоматически заполнить пустую БД демо-данными |
| `COOKIE_SECURE` | `false` в dev, `true` в production | Cookie сессии только по HTTPS. Для локальной проверки production через HTTP явно укажите `false` |

## Демо-данные

`src/seed-data.ts` — пользователи, публикации, проекты, чаты из макета. Email и пароль демо-аккаунтов
указаны там же (`DEMO_EMAIL`, `DEMO_PASSWORD`). Команда `npm run seed` выполняет явный разрушительный сброс демо-базы; не используй её для сохранённых рабочих данных.

`NODE_ENV=production` выключает автоматическое заполнение по умолчанию. Явное `SEED_DEMO_DATA=true` включает его даже в production. Явная команда `npm run seed`
по-прежнему создаёт их и удаляет существующие данные. Эти настройки не удаляют уже созданные демо-аккаунты:
при `ALLOW_DEMO_LOGIN=false` обычный `/login` тоже блокирует известные seed email с их публичным паролем.
Аккаунт с тем же email и изменённым паролем остаётся доступным. Для развёртывания используйте
отдельную чистую БД без публичных тестовых паролей.

## Устройство

```
src/
├── index.ts          # старт: сид при пустой базе + listen
├── app.ts            # Express: middleware, роуты, обработка ошибок, раздача фронтенда
├── config.ts         # переменные окружения (+ загрузка backend/.env)
├── db.ts             # подключение SQLite, схема (CREATE TABLE IF NOT EXISTS), хелперы all/get/run/tx
├── auth.ts           # scrypt-хэши паролей, сессии в httpOnly-cookie, requireAuth
├── models.ts         # строки БД → JSON для фронтенда
├── seed.ts           # заполнение базы
├── seed-data.ts      # демо-контент
└── routes/           # auth, opportunities, conversations, users (+ projects)
```

- **Авторизация:** cookie `qadam_session` (httpOnly, SameSite=Lax), в базе хранится только SHA-256 токена. Сессия живёт 30 дней.
- **Пароли:** вход и регистрация используют асинхронный scrypt. Синхронный helper оставлен для явной загрузки демо-данных.
- **Попытки входа:** `/register`, `/login`, `/demo` вместе допускают 30 запросов с IP за 15 минут и 10 с одной парой IP/email.
  При превышении — `429 { error, retryAfter }` и заголовок `Retry-After` в секундах. Ограничитель работает в памяти
  одного процесса; для нескольких экземпляров нужен общий счётчик. IP берётся из Express без доверия произвольному `X-Forwarded-For`.
- **Валидация:** zod; ошибка — `400 { error, issues }`. Не вошёл — `401`, нет прав — `403`, не найдено — `404`.
- **Схема** создаётся без удаления существующих таблиц и данных. Для переноса сохраняй согласованный SQLite-снимок; не удаляй `data/`.

## API

Все ответы — JSON. 🔒 — нужен вход.

### Авторизация `/api/auth`

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| POST | `/register` | `{ name, email, password, city? }` | `{ user }` + cookie |
| POST | `/login` | `{ email, password }` | `{ user }` + cookie |
| GET | `/options` | — | `{ demoLogin }`, публичная возможность обычного демо-входа |
| POST | `/demo` | — | вход в демо-аккаунт (если `ALLOW_DEMO_LOGIN`) |
| POST | `/logout` | — | `204` |
| GET | `/me` | — | `{ user \| null }` |

### Публикации `/api/opportunities`

| Метод | Путь | Описание |
|---|---|---|
| GET | `/?city=&kind=&q=&online=1&author=` | Список (`kind`: `meetup` · `job` · `idea` · `event`; `author=me` — свои) |
| GET | `/:id` | Одна публикация |
| POST 🔒 | `/` | Создать: `{ kind, title, description, city, roles[], direction?, stage?, online?, size?, deadline?, cover?, date?, time?, place?, coords? }`. Заодно появляется в «Моих проектах» |
| DELETE 🔒 | `/:id` | Удалить свою |
| POST 🔒 | `/:id/apply` | Заявка `{ role, message, portfolio? }` → уходит автору в личный чат, ответ `{ application, conversationId }` |
| DELETE 🔒 | `/:id/apply` | Отозвать заявку |
| PUT / DELETE 🔒 | `/:id/attend` | «Я пойду» / отменить |
| PUT / DELETE 🔒 | `/:id/save` | Сохранить / убрать из сохранённого |

Для `kind=event` обязательны `date` (существующая календарная дата `YYYY-MM-DD`), `time` (`HH:mm–HH:mm`,
окончание позже начала), `place` (адрес/название площадки) и `coords: [latitude, longitude]` с валидными диапазонами.
Точка обязательна и при `online=true`. Эти значения сохраняются без подмены; `deadline` остаётся сроком набора,
а не датой события. Город должен входить в `CITY_COORDS`. У остальных видов публикаций точка без `coords`
пока приблизительная, в пределах выбранного города.

### Пользователи и проекты

| Метод | Путь | Описание |
|---|---|---|
| GET 🔒 | `/api/users/me` | `{ profile, publications }` |
| PATCH 🔒 | `/api/users/me` | Изменить профиль: `name, role, city, bio, about, portfolio, skills[], interests[]` |
| GET 🔒 | `/api/users/me/state` | `{ saved[], attending[], applications[], unread }`; у заявки `{ opportunityId, role, createdAt, conversationId: string \| null }`. Чтение состояния не создаёт диалоги |
| GET 🔒 | `/api/users/me/activity` | Вкладки профиля: `{ requests[], saved[] }` |
| GET | `/api/users/:id` | Публичный профиль + публикации |
| GET 🔒 | `/api/projects` | «Мои проекты»: свои и где участвую |

### Чаты `/api/conversations` 🔒

| Метод | Путь | Описание |
|---|---|---|
| GET | `/` | Диалоги с последним сообщением и счётчиком непрочитанных |
| POST | `/direct` | `{ userId }` → найти или создать личный диалог, `{ id }` |
| GET | `/:id` | `{ conversation, messages[] }` |
| POST | `/:id/messages` | `{ text }` → `{ message }` |
| POST | `/:id/read` | `{ messageId }` — отметить прочитанным до полученного сообщения этого диалога; более старое подтверждение не откатывает курсор |

Новые сообщения фронтенд получает опросом (каждые 4 с в открытом чате); WebSocket можно добавить позже.
Подтверждение должно содержать ID последнего реально полученного сообщения. Отправка ответа сама по себе
не отмечает входящие сообщения прочитанными.

## Бесплатные публикации и повторная отправка

Публикации бесплатны без месячной квоты, проверки оплаты, студенческого статуса или пакетов. Старое окружение `BILLING_MODE` игнорируется. Маршруты `/api/billing/*`, `/api/campus/*`, `POST /api/auth/campus-demo` и административные команды этих функций удалены.

`POST /api/opportunities` принимает необязательный `Idempotency-Key`. Для одного пользователя тот же ключ с тем же валидным телом возвращает прежнюю публикацию и статус 201. Другое тело получает 409; удалённая публикация — 410. Ошибка валидации или откат транзакции не занимают ключ. Создание публикации, проекта и ключа выполняется в одной SQLite-транзакции. Запросы без ключа совместимы с прежним API.

## Совместимость существующей базы

Отменённые функции не создают таблицы и не записывают историю использования. Уже существующие таблицы `billing_*` и `campus*` остаются в SQLite: нет DROP, удаления записей, переноса квот или автоматического сброса. Сохранённые ключи прежних запросов читаются для безопасного повтора; новые записываются только в `publication_requests`.

Остаются две защитные проверки старых данных: ранее скрытая публикация доступна только её автору и не становится публичной после удаления модерации; старые выделенные демонстрационные аккаунты не могут войти по паролю или прежней cookie. Их записи и сессии при такой проверке не удаляются. Прежние вузовские роли не дают прав доступа. Обычные аккаунты и их авторизация сохраняются.

`seed --reset` отказывается работать с непустыми архивными таблицами, чтобы не стирать сохранённые данные и не нарушать внешние ключи. Для отдельного демо выбери новый `DB_PATH`. Сборка должна быть обновлена перед запуском: удалённые модули старого `dist/` больше не импортируются приложением.
